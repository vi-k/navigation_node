## Откуда взялся этот репозиторий

Пакет жил внутри [scopo](https://github.com/vi-k/scopo) до её версии 0.11.0 и
вынесен 2026-08-24 по находке U7 её потребительского ревью
(`docs/records/2026-08-23[1]-consumer-review.md` там же). Причина: он не
импортирует ничего, кроме Flutter, внутри scopo им не пользовалось ничто, а
человек, ищущий вложенный навигатор, не нашёл бы его в пакете про
dependency injection. Измерение и цена вариантов — в записи
`docs/records/2026-08-24[1]-navigation-node-boundary-design.md` репозитория
scopo.

Код, сьюта и пример перенесены **без изменений поведения**. Изменилось только
то, что связывало их со scopo:

- `{@category utils}` снят с трёх публичных объявлений — тема `utils` осталась
  в scopo;
- у `PreviousNavigatorExtension` появился свой дартдок: раньше вместо него
  стояла одна строка `{@category utils}`, и без неё `public_member_api_docs`
  краснел;
- сьюта клала над узлом `ScopeModel<_Config>`, чтобы проверять, видит ли
  маршрут то, что лежит над экраном. Теперь это `_ConfigScope` —
  `InheritedWidget` в самом файле теста, с чтением через
  `getInheritedWidgetOfExactType` (это ровно прежний `listen: false`);
- в примере `ScreenScope` был `ScopeModel<Ticket>`, стал `InheritedWidget`,
  несущий `Ticket`; `main()` больше не ставит `ScopeConfig.observer`.

**Ссылок на scopo в пакете не осталось нигде**, кроме двух намеренных: раздел
README «Where it comes from» и ссылка на `scopo_demo` из README примера.

## Где мы сейчас

На pub.dev — **0.1.1, опубликована 2026-08-24**, в тот же день, что и 0.1.0:
[pub.dev/packages/navigation_node](https://pub.dev/packages/navigation_node).

Что в неё вошло, кроме первой правки — отчёт об ошибке из узла называл библиотеку
`scopo`, теперь `navigation_node`, — это ревью 2026-08-24 целиком
(`docs/records/2026-08-24[1]-post-extraction-review.md`, четырнадцать находок:
двенадцать исправлено, одна закрыта документацией, одна отклонена). Дефекты:
вечный цикл `popUntil` внутри узла, пропадающее нажатие, когда `canHandlePop`
пришло от чужого навигатора, выключенный узел, глушивший системное «назад»,
устаревшее решение `onPop` после выключения узла, три непокрытых пути отчёта об
ошибке. Прибавка: именованные маршруты внутри узла работают и остаются внутри
него — навигатор узла одалживает таблицу у навигатора сверху. Каждая правка
держится тестом, нагруженность каждого проверена откатом.

**0.2.0 готова, но не опубликована**: наблюдатели внутри узла.
`NavigationNode(observedFromAbove:)` — `true` по умолчанию, узел наследует
наблюдателей навигатора сверху; `NavigationNode(observers:)` называет
наблюдателей для одного узла. Отдать чужие экземпляры навигатору узла нельзя
(Flutter привязывает наблюдателя к одному навигатору и стережёт это
утверждением), поэтому узел вешает свой `_NodeObserver` и пересказывает ему семь
хуков. О собственной странице узел молчит ровно при монтировании. Заказ пришёл
от соседнего проекта; устройство и отклонённые варианты — в
`docs/records/2026-08-26[1]-observers-design.md`, находки четырёх независимых
ревью и вердикты — в `2026-08-26[2]-observers-review-report.md`, второй заход по
самим правкам — в `2026-08-26[3]-delta-review-report.md`.

**Почему 0.2.0, а не 0.1.2**: API правка не ломает, но обновившийся потребитель
начинает кормить свои наблюдатели событиями из узлов, ничего у себя не тронув.
Владелец выбрал номер, который предупреждает сам. Следствие для соседнего
репозитория: `example/scopo_demo` в scopo стоит на `^0.1.0` и 0.2.0 не
подхватит — ограничение там придётся поднять руками.

**Из известных ограничений осталось одно** (`README.md`, раздел «What a node
does not do»): узлу не передан `restorationScopeId`, поэтому стек внутри узла не
восстанавливается. Соседи об этом просить не стали — `restorationScopeId` и
`RestorationMixin` у них не встречаются нигде, — так что оно по-прежнему ждёт,
понадобится ли кому-нибудь.

**Окно ломающих правок этим закрыто.** До публикации переименовать или убрать
публичное имя стоило ноль; теперь каждое такое изменение стоит версии, и решать
это владельцу.

**Репозиторий обустроен по образцу scopo** (2026-08-24): `CLAUDE.md` со
ссылкой на `AGENTS.md`, полный регламент в `AGENTS.md` (восемь разделов),
`docs/backlog.md` для записей владельца, **`docs/architecture.md`** — устройство
узла изнутри: из чего он собран, путь одного нажатия, три вещи, которые легко

## Найдено по пути и не чинилось

**`pushReplacement` и `pushAndRemoveUntil((_) => false)` на первой странице узла
падают** на ассерте фреймворка «A page-based route cannot be completed using
imperative api»: страница узла page-based, а защищён от этого только `popUntil`
— переопределением в `NodeNavigatorState`. В README и дартдоках об этом ни
слова. Нашлось ревью наблюдателей 2026-08-26, к нему отношения не имеет.

**`.github/workflows/ci.yml` ссылается на «`AGENTS.md` §4»**, а гейт — §6.

## Грабли, на которые не стоит наступать второй раз

**Перехватил `FlutterError.onError` — передай дальше.** Тест, который читает
`FlutterErrorDetails`, ставит свой обработчик; если не позвать из него прежний,
биндинг не получает ошибку, `tester.takeException()` возвращает `null`, а
`pumpAndSettle` ждёт своего десятиминутного таймаута вместо двух секунд. Так и
выглядело: прогон висел ровно 10:01. Пишется так:

```dart
final previous = FlutterError.onError;
FlutterError.onError = (details) {
  reported.add(details);
  previous?.call(details);
};
addTearDown(() => FlutterError.onError = previous);
```

**У `macOS` нет `timeout`.** `timeout 240 fvm flutter test` кончается кодом
127 и пустым выводом — это «команда не найдена», а не упавший прогон.
