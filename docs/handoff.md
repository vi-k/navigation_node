## Ручной гейт перед публикацией: как проверять урок 10

`d0c5046` не держится ни одним тестом и не может: тестовая VM собирает функцию
по имени, настоящее приложение — нет. Проверяется только запуском, и вот чем
именно.

**Настоящее убийство ОС тут не нужно и ничего не покажет.** Карманный менеджер
урока намеренно не подключён к движку (`initChannels` пуст), а у `MaterialApp`
примера нет `restorationScopeId` — байты не доходят до системы и умирают вместе
с процессом. После настоящего kill приложение начнётся со списка уроков, и это
не дефект, а устройство урока.

**Проверять надо кнопку.** Ошибка `closurize` приходит из
`PluginUtilities.getCallbackHandle`, который фреймворк зовёт при сериализации, —
карманный менеджер запускает ровно этот путь. Потому дефект и нашёлся на macOS,
где платформенного восстановления нет вообще.

Две вещи решают (обе из `docs/records/2026-08-26[5]`):

- **входить в урок через список, а не стартовым экраном** — прогон стартовым
  экраном был чист, а через список падало с первого нажатия;
- **повторить несколько раз** — один зелёный прогон флаки-сценария не
  доказывает ничего: первый ноль оказался везением, повтор дал четыре ассерта.

В консоли смотреть `closurize`, `schedulerPhase == SchedulerPhase.idle` и
`markNeedsBuild`; ждём нулей по всем трём. Владелец собирался проверить на
Android — годится, нужна настоящая VM, а не настоящий kill.

Если захочется проверить **платформенное** восстановление по-настоящему, это
другая работа: примеру понадобится `MaterialApp.restorationScopeId` и
восстановимый маршрут к уроку.

**Что в 0.2.0**: наблюдатели внутри узла.
`NavigationNode(observedFromAbove:)` — `true` по умолчанию, узел наследует
наблюдателей навигатора сверху; `NavigationNode(observers:)` называет
наблюдателей для одного узла. Отдать чужие экземпляры навигатору узла нельзя
(Flutter привязывает наблюдателя к одному навигатору и стережёт это
утверждением), поэтому узел вешает свой `_NodeObserver` и пересказывает ему семь
хуков. О собственной странице узел молчит ровно при монтировании. Заказ пришёл
от соседнего проекта; устройство и отклонённые варианты — в
`docs/records/2026-08-26[1]-observers-design.md`, находки четырёх независимых
ревью и вердикты — в `2026-08-26[2]-observers-review-report.md`, второй заход по
самим правкам — в `2026-08-26[3]-delta-review-report.md`.

**Почему 0.2.0, а не 0.1.2**: API правка не ломает, но обновившийся потребитель
начинает кормить свои наблюдатели событиями из узлов, ничего у себя не тронув.

## Чего здешние тесты поймать не могут

**Зелёная сьюта не доказывает, что пример работает.** Тестовая VM собирает
функцию по имени и без `@pragma('vm:entry-point')`, а настоящее приложение —
нет: восстановимый маршрут падал в движке при зелёном гейте. Если трогаешь
восстановление или что-нибудь ещё, что фреймворк достаёт по имени, **проверяй
запуском**, а не прогоном.

Как это делать, не пачкая рабочее дерево чужим SDK: `git clone . <куда-то>`,
и уже там `flutter run -d macos`. Приложение можно заставить нажимать на себя
само — таймер в `initState` урока, — и читать консоль из лога. Так найден
`d0c5046`; разбор — в `docs/records/2026-08-26[5]-restoration-design.md`.

**И постановка опыта решает.** Тот же урок, открытый стартовым экраном, был
чист; открытый через список — падал с первого нажатия. Воспроизводить надо тот
путь, которым ходит человек.

## Грабли, на которые не стоит наступать второй раз

**Перехватил `FlutterError.onError` — передай дальше.** Тест, который читает
`FlutterErrorDetails`, ставит свой обработчик; если не позвать из него прежний,
биндинг не получает ошибку, `tester.takeException()` возвращает `null`, а
`pumpAndSettle` ждёт своего десятиминутного таймаута вместо двух секунд. Так и
выглядело: прогон висел ровно 10:01. Пишется так:

```dart
final previous = FlutterError.onError;
FlutterError.onError = (details) {
  reported.add(details);
  previous?.call(details);
};
addTearDown(() => FlutterError.onError = previous);
```

**У `macOS` нет `timeout`.** `timeout 240 fvm flutter test` кончается кодом
127 и пустым выводом — это «команда не найдена», а не упавший прогон.
