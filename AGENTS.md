# AGENTS.md — точка входа для агентов

Регламент работы над пакетом **navigation_node** для Claude Code и Codex.
Правила те же, что в [scopo](https://github.com/vi-k/scopo) — пакет вырос
оттуда, — и здесь записаны в сокращённом виде: один пакет, один пример.

## 1. Начало сессии

1. Прочитай **`docs/handoff.md`** — состояние: на чём остановились, что
   сломано, что проверено.
2. Сверь с репозиторием: `git log --oneline -10`, `git status`.

Пока не прочитан `docs/handoff.md`, никаких правок в коде.

## 2. Поддержание состояния

**`docs/handoff.md` должен быть актуален всегда**, а не только в конце сессии:
она обрывается без предупреждения, и всё, что не записано, теряется. Обновляй
его, когда сделан заметный шаг, когда меняется направление работы и перед
длинной операцией.

История правок — в `docs/records/`, если она понадобится: имя файла
`YYYY-MM-DD[N]-name-kind.md`, где `kind` — `design`, `plan`, `report`,
`review` или `log`; каждый файл начинается с H1 и шапки текущего состояния.

## 3. Git

- **Мержим прямо в `main`, без PR.**
- **Не коммить чужие правки вместе со своими.** Перед коммитом — `git status`
  и `git diff`; коммить свои файлы поимённо, а не `git add -A`.
- Сообщения коммитов на английском, с префиксом: `feat:`, `fix:`, `docs:`,
  `refactor:`, `test:`, `chore:`.
- Не публиковать пакет (`dart pub publish`) без явной просьбы владельца.

## 4. Проверки

Тулчейн — **Flutter 3.27.0 через fvm** (`.fvmrc`, `.fvm/` и
`.vscode/settings.json` не под контролем версий). Это ровно тот пол, что
заявлен в `pubspec.yaml`: команды ниже и есть проверка пола.

```sh
fvm flutter test                     # все зелёные; число — в docs/handoff.md
fvm flutter analyze                  # корень; обходит и example/
fvm dart format --set-exit-if-changed lib test
fvm dart doc --dry-run               # 0 warnings, 0 errors
fvm dart pub publish --dry-run       # 0 warnings
sh docs/ru/check.sh                  # переводы отвечают оригиналам
(cd example && fvm flutter analyze && fvm flutter test)
```

Перед мержем в `main` проходят все семь. Утверждать «работает» без вывода
команды нельзя: сначала прогон, потом заявление.

**Прогнал что-то другим SDK** — глобальным `flutter` с `PATH` или через
`fvm spawn <версия>` — сразу после этого `fvm flutter clean && fvm flutter pub
get`: чужой движок оставляет в `.dart_tool` свой кеш, и следующий прогон падает
на `Asset 'shaders/ink_sparkle.frag' ... Expected 2, got 0`. Дефекта в коде при
этом нет.

**`docs/` не публикуется** — исключена в `.pubignore` вместе с `AGENTS.md` и
`CLAUDE.md`. Сьюта тоже: 58 КБ против 26 КБ `lib/`, и потребителю она не нужна.

## 5. Язык

- Документы для владельца и агентов (`AGENTS.md`, `docs/`) — **по-русски**.
- Публичные артефакты — **по-английски**: `README.md`, `CHANGELOG.md`,
  dartdoc-комментарии, сообщения коммитов, тексты ошибок.

**Русские зеркала публичных документов** — в `docs/ru/`, по путям оригиналов:
`docs/ru/README.md`, `docs/ru/example/README.md`. Правка оригинала не
заканчивается без правки перевода **в том же коммите**; после правки —
`sh docs/ru/stamp.sh` (переносит blob-хеш оригинала в шапку перевода),
расхождение ловит `sh docs/ru/check.sh`. Комментарии внутри примеров кода в
зеркалах тоже переводятся, кроме директив `// ignore: …`.

`stamp.sh` не читает текст и не отличит обновлённый перевод от устаревшего.
Запуск «чтобы гейт замолчал» — это ложь в проверке, а не её прохождение.

## 6. Как здесь принято работать

- **Сначала тест.** Дефект — сперва падающий тест, потом исправление.
  Исправил — откати правку и убедись, что тест падает.
- **Не расширяй объём молча.** Нашёл смежную проблему — запиши в
  `docs/handoff.md`, а не чини заодно.
- **Отчитывайся честно.** Тесты упали — покажи вывод.
- Правки в `lib/` без обновления `CHANGELOG.md` не заканчиваются.
